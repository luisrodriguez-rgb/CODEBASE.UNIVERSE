## 1. Why CODEBASE.UNIVERSE?

### The "Particle Hairball" Problem
Traditional code visualization tools dump tens of thousands of unweighted dots into a spherical force-directed cloud. While visually dazzling for five seconds, they offer **zero architectural hierarchy**, **zero actionable insight**, and **zero refactoring utility**. You cannot see where execution starts, which module is a single point of failure, or how a breaking change cascades downstream.

### The Citadela Paradigm
**CODEBASE.UNIVERSE** treats software as a physical city:
- **Mass Encodes Code Complexity:** High-LOC God classes manifest as towering monoliths; lightweight utility functions sit as modular residential blocks.
- **Windows Encode Cyclomatic Debt:** Internal branching decisions (if/else/switch/catch) light up illuminated matrices across building facades.
- **Beacons Encode System Criticality:** Skyward vertical light beams project only from architectural landmarks (percentile 95+ betweenness centrality).
- **Zoning Encodes Runtime Boundaries:** Code is partitioned into 8 functional districts so UI never gets confused with database layers or transmission gateways.

### The Problem with Traditional AI Agent Discovery
AI coding agents (Antigravity, Cursor, Claude Code) typically grep and read entire files (thousands of lines) to locate functions. This burns **30k - 100k tokens per prompt**, triggers "lost in the middle" hallucinations, and blinds the agent to downstream breaking changes.

### The MCP Subgraph Solution (90%+ Token Reduction)
By querying the `codebase-memory-mcp` knowledge graph, the AI agent performs **surgical context extraction**:

```text
┌────────────────────────────────────────────────────────────┐
│ TRADITIONAL DUMP vs CODEBASE-MEMORY-MCP                    │
├────────────────────────────────────────────────────────────┤
│ Traditional File Dumps:  ~85,000 Tokens (Slow & Expensive) │
│ Subgraph Neighborhood:   ~1,150 Tokens (98.6% Token Saved) │
└────────────────────────────────────────────────────────────┘
```

1. **Targeted Subgraph Neighborhood:** The agent calls `search_graph()` or `get_code_snippet()` to receive only the immediate 1st-degree callers and callees.
2. **Dijkstra Call Path Tracing:** The agent invokes `trace_path(origin, target)` to inspect only the exact execution chain instead of 30 unrelated files.
3. **Pre-Edit Blast Radius Verification:** The agent validates changes against the graph before applying diffs, preventing circular deadlocks and broken contracts.
